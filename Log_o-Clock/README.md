# Log O'clock

Created by Zachariasz Jędrzejczyk.

A lightweight, local-first Windows time tracker inspired by Toggl. It organizes work as clients, projects, saved tasks, and optional descriptions, while reminding you to start a timer when a configured project appears in the active window title.

Developer handoff and architecture documentation starts at [docs/README.md](docs/README.md). New development contexts should read [docs/NEW_CONTEXT.md](docs/NEW_CONTEXT.md) before making changes.

The Windows interface uses a Codex-inspired dark design with a compact custom title bar, beveled panels, translucent glass surfaces, and native Windows 11 backdrop effects with a dark fallback on Windows 10.

All application-owned interface text uses English (UK), independently of the Windows display locale. History day headings use English weekday and month names, short dates remain day-first, times remain 24-hour, and dark calendars inherit the same English language. User-created descriptions, clients, projects, tasks, tags, and other stored content are never translated or rewritten.

The top-right minimize, maximize/restore, and close controls use compact 31 px hit areas with proportionally scaled icons, while retaining their hover and pressed feedback.

Maximizing the custom window uses the active monitor's working area, so the app fills the available screen without covering a taskbar docked on any edge.

The History date-range panel is 235 px wide, comfortably showing the full `DD.MM.YYYY - DD.MM.YYYY` manual range format while retaining the same dark calendar.

The History tag filter is compact too, keeping its colored tag names, filtering behavior, and full value in the dropdown.

History project, task, and tag dropdown rows are protected from the global click-away focus reset, so clicking a filter value always commits it before the entry list is refreshed.

Targets in the fixed and collapsed sidebars remain visually neutral on hover and after clicking; context actions, progress rings, and target completion colors remain available.

The fixed sidebar target panel can be resized vertically by dragging its top edge. Its target list expands or squeezes with smooth scrolling, growth stops before covering the navigation tabs, and the preferred height is saved separately for each profile and restored on later launches.

Each sidebar project appears once. Its daily, weekly, and monthly targets share one overlaid progress ring: daily is orange, weekly is purple, and monthly is bright green. Multiple targets of the same cadence are summed into that project row; longer arcs render first and the shortest arc renders last on top. Global targets share one `All projects · Every client` row.

The Software tab project filter formats each option as `Project · Client`, using the same true middle-dot separator and spacing as the Tasks tab filter.

The supplied clock artwork is embedded as the executable, installed shortcut, Windows taskbar, dialog-title, and Add/Remove Programs icon. The tray deliberately retains its separate compact gray idle and green running icons.

## Included behavior

- Settings is organized into compact, independently scrollable `Tracking`, `Idle & sessions`, `Targets`, `Integrations`, and `Application` subtabs. Existing options keep their original behavior, while related session/idle policies and Trello/Google Sheets connections stay together.
- English interface culture is applied centrally to app labels, generated statuses, dates, times, calendars, and dialogs. History groups render dates such as `Wednesday, 15 July 2026` even on a Polish Windows account, while compact dates use `DD.MM.YYYY` and user-authored data is preserved exactly.
- Local profiles provide completely separate workspaces for people sharing one Windows account. The title-bar profile selector switches, creates, renames, and removes profiles. Each profile has its own clients, projects, tasks, tags, software, rules, targets, settings, history, SQLite database, and monthly CSV logs. Switching safely stops a running timer after confirmation and relaunches the single tray instance into the selected workspace. Existing installations become the built-in, renameable Default profile without moving their data. Removed secondary profiles are archived under `Profiles\Removed` instead of being immediately erased.
- Optional read-only Trello synchronization is configured independently for each profile. Settings guides you through a personal Power-Up API key and browser-generated read token, stored in Windows Credential Manager rather than SQLite. Map one Trello board and selected open lists to a local project; every open card assigned to the connected Trello account becomes an ordinary selectable tracker task. Synchronization runs at profile startup, every 15 minutes, and on demand. Trello controls linked task names, duplicate card names remain distinct by card ID, and card descriptions, labels, comments, attachments, and activity history are never imported.
- When a synchronized card leaves its selected lists, is archived, or is no longer assigned to the connected account, an unused task is removed. A task with recorded time is detached into a normal editable local task and keeps all history; if the card qualifies again, that same task is re-linked. Manually removing a linked task suppresses it so automatic synchronization does not recreate it. Network failures preserve the last synchronized tasks for offline use, while expired authorization is reported in Settings without exposing credentials.
- Optional Google Sheets synchronization shares an entire profile between computers while each device keeps SQLite as its fast offline working database. Settings can create a spreadsheet or join an existing Log O'clock spreadsheet from an empty profile. Completed logs, clients/projects/tasks, tags, configured software and rules, targets/debt, Trello mappings, stable preferences/layouts, and the profile name reconcile through hidden app-managed worksheets. Running timers stay local and appear on other devices only as read-only composer/tray status. Concurrent edits enter a persistent review queue with local/cloud/both and delete/restore choices; unaffected work continues synchronizing. See [Google Sheets profile synchronization](docs/GOOGLE_SHEETS_SYNC.md) for the protocol, privacy boundary, conflict semantics, and multi-device release checklist.
- Daily Google worksheets remain readable derived views grouped in an explicitly pinned profile time zone. They include call state plus creation/modification timestamps with offsets, are rebuilt globally by entry ID when dates move, and overwrite manual sheet edits. OAuth secrets, Trello credentials, local runtime/review markers, unknown observed window titles, and audio/media observations never enter the shared journal. All computers sharing a profile must use the schema-27 sync-capable release.
- One active timer with tray controls, crash checkpoints, pending-detail reminders, and manual entry editing.
- Break reminders appear after every configured amount of net active timer time (two hours by default). They continue through project switches and rips, reset when tracking stops or an idle review occurs, close after three seconds, and can be positioned at the bottom-right or centre of the primary screen in Settings. Settings also lets each profile enable or disable built-in messages; each reminder randomly selects among the least-used eligible messages for the local day. Dinner is eligible from 12:00 to 18:00 and the short-episode reminder from 10:00 to 22:00.
- Starting work can automatically reopen the immediately previous unpaid entry when its project, task, description, and tags all match. The gap is counted as tracked time and must be strictly shorter than the configurable Settings threshold (two minutes by default); `0` disables merging. Different or intervening work, an exact-threshold gap, and paid entries always create a new log.
- Wide lists support smooth two-axis navigation: the mouse wheel continues to scroll vertically, while horizontal touchpad or tilt-wheel gestures scroll left and right with pixel-based motion. Automatic horizontal overflow is enabled across History, Reports, Clients & Projects management lists, targets, reminders, and editor lists, with nested lists handing movement to their parent at an edge.
- Daily project targets that have been met or exceeded are filled with `#257D57` behind their daily progress line in both the pinned sidebar and Reports target list; weekly and monthly lines keep their normal neutral treatment.
- A single tray click while tracking reopens the current entry with its saved task and description. Changes autosave while editing and on click-away, so there is no redundant Done button. The popup provides `Rip from this moment` and `Stop timer`; Stop saves the visible values before using the normal stop-and-review flow.
- The tray menu's primary Start timer action begins immediately without requiring a project or task. A persistent hidden Unassigned entry is created first, then the compact popup lets you choose the project, select or type the task, and enter a description; project-specific quick starts remain available under Start for project. While tracking, `Stop timer` keeps the completed entry and opens its normal details review, while `Cancel current timer` immediately discards the local running entry without confirmation or a History record.
- While tracking, the tray hover tooltip is task-first and omits the client: `Task · Project — HH:MM:SS`. Entries without a task show `Project — HH:MM:SS`; long labels are shortened without hiding the live elapsed time.
- The timer project selector shows project first, a muted purple-gray separator dot, and client second in a dark popup with a deep-green selected row.
- The timer bar is ordered Task → Project → Description. Typing in its task field immediately opens a case-insensitive search dropdown of matching tasks in the selected project, with prefix matches first. Opening search preserves the first typed character and caret instead of selecting the text again. Clicking a task result commits its name and updates the running entry. The project chooser remains available while tracking and reassigns the running entry immediately; dropdown rows are protected from the shell's click-away handler so project and task clicks cannot be discarded.
- Clicking a non-editable app surface clears active keyboard focus from text fields without losing their draft values. In the timer bar, moving to another field also closes the previous task/project dropdown.
- Tracker fields, filters, buttons, switches, and chooser controls use neutral gray focus/active feedback without persistent blue outlines. History and Reports date shortcuts retain the same bright-gray selected surface as tabs whenever their current range is Today, This week, or This month.
- The automatic details popup opened after a recognition start uses the same editable task chooser as the timer bar: select a saved task or type a new name directly. Typed names are created or reused automatically on autosave, Enter, click-away, or Rip, with no separate Add button. A notification-created task is removed automatically if it ends up with no entries; tasks deliberately created in the Tasks tab are retained.
- Choosing an existing task from that popup's dropdown immediately replaces any text previously typed in the task field, then autosaves the selected task and updates the top timer bar.
- Client, project, task, tag, rule, and time-entry editing is consistently available by double-clicking a row. Add/edit/remove actions live in right-click menus: tabs that allow creation show Add when empty space is right-clicked, with no duplicate CRUD button bars below the lists.
- Client, project, and task management. Removing a project—or a client containing projects—is permanent: its entries, tasks, targets, rules, project settings, and correlated metadata are deleted and monthly CSV logs are regenerated. The confirmation dialog states this explicitly. Removing only a saved task still archives it so existing history remains readable.
- Projects can be frozen from the Projects row context menu without deleting any entries, tasks, targets, or settings. Frozen records are dimmed in a collapsed `Freezed Projects` section at the bottom of the Projects, Tasks, Tags, Targets, Software, and Window rules views; they are removed from new-entry project choosers, and recognition rules are disabled until their prior states are restored on unfreeze.
- Clients displayed as neutral, collapsed rows with expandable lists of their assigned projects.
- Task-first management view with project, client, and all-time net duration columns. A compact project filter shows `Project · Client`, limits the list to the selected active project, preselects it when adding a task, and resets to `All projects` whenever Tasks is entered.
- Project-first management view with colored project names, all-time net totals, first/latest activity dates, blank-space creation, and an HSV color wheel.
- Software is added only through the Software tab, including its manual process field and Capture active process action. Its Project scope offers `No project · Global · every project`: global software records usage in every project and shares one exclusion/tag configuration, while project-scoped software records only in explicitly assigned projects and keeps tags/exclusion project-specific. Unknown processes are ignored and never create rows automatically. The tab shows the immutable process name and an editable display label, and label changes update History, entry editing, CSV exports, and synchronized monthly logs.
- Right-click a Software row and choose `Remove from list` to remove that process from Software management and from every historical entry, export, and synchronized monthly log. Project-specific exclusions and correlated tags are cleared too. Adding the same process later restores its list record but deliberately starts with no historical associations.
- Add Software includes `Capture active process in 3 seconds`, matching Window Rules capture behavior. The dialog minimizes so you can activate the target application, then restores with its process name filled in. A blank editable display label is initialized from the captured process and can be changed before saving.
- Add/Edit Software reserves a three-row, wrapping viewport for correlated tag chips. Additional tags use smooth vertical overflow rather than compressing the editor, while excluded software keeps the complete area visibly disabled.
- Software exclusion is configured per project. A process can be excluded from Project A while remaining tracked in Project B. Visits are accumulated independently per excluded process and do not prompt until that process reaches the configurable threshold (five minutes by default). Each process asks once per running entry; the Keep/Cut decision applies automatically to its later visits, and Cut preserves the separate intervals so work between visits remains counted. The threshold is editable in Settings. A process excluded for a recognized project does not trigger that project's reminder or become associated with its new entries.
- Software-tag correlations are also per project. The same process can suggest animation tags in one project and rigging tags in another. In both the Software editor and a matched-project reminder, unused/unchecked tag chips are neutral gray, while a selected chip fills with its assigned tag color and uses white text. Selected reminder tags are appended to the new entry description in brackets and remain editable alongside manually typed `#tags`.
- Add/Edit Software accepts new correlated tags directly above the tag chips. Finishing a valid name with a comma converts it into a uniquely colored chip and selects it by default. Existing names select their existing chip case-insensitively without duplication. New tags inherit the software scope: project software creates a project-related tag, while global software creates a global tag available to every project.
- Enabling `Exclude this software from tracked work` gives its switch the same bright-gray track and dark thumb as enabled Settings switches, without adding a focus outline. The correlated-tags editor is hidden because excluded software cannot trigger project tag suggestions; unchecking exclusion restores editing and preserves the previous tag selections.
- The Software editor’s Exclude switch uses the same neutral bright-gray selected fill as an active tab when enabled. Its thumb remains the state indicator, with no blue focus outline.
- The recognized-project reminder also contains the standard editable task chooser and a tag-aware description field. After a project match, the active window title is compared in memory with that project's active saved tasks. One unambiguous longest task-name match is selected, with case and punctuation/separator differences ignored. When no saved task is recognized and the title contains a path ending in a filename with an extension, the editable task field instead receives the filename without its extension; camel-case transitions are spaced, so `BoulderWalkF.fbx` becomes `Boulder Walk F`. The fallback is persisted only when Start is accepted. A matching non-Trello saved task whose name differs from that filename only in whitespace is corrected in place, preserving its identity and history; Trello-controlled names are never changed. Without a usable filename the field remains blank. When typing, the chooser opens automatically and filters that project's tasks by case-insensitive partial name, ranking matches from the beginning first exactly like the main tracker bar. Existing tasks can still be selected, unmatched text remains a new task name, and Start carries the task, description, and toggled software tags into the running entry without opening a second task-update popup. The usual details review is still available from the tray and when stopping an incomplete entry.
- A recognized-project reminder appears on the monitor containing the active matched software window, positioned in that monitor's lower-right working area. If Windows cannot resolve the window monitor, it uses the normal primary-display placement.
- Accepting a recognized-project reminder is independent from the expired foreground debounce token, so returning focus to the recognized software cannot cancel the requested timer start.
- While a timer is running, recognizing the same project stays silent. Recognizing a different project opens a switch reminder; accepting it stops the current entry and starts the recognized project at one exact boundary while keeping each entry's task and description isolated.
- Case-insensitive window-title rules with optional process filtering, longest-rule selection, and safe handling of ambiguous matches.
- A recognized-project reminder remains visible without timing out. For its first three seconds, clicking elsewhere cannot discard it; after that guard expires, the next mouse click outside dismisses it. Clicks inside continue to select tasks or tags and start tracking immediately.
- The top-right `Gimme break!` control on a recognized-project reminder closes it without starting a timer and pauses all recognition prompts for five minutes. Its tooltip appears after a two-second hover, and the current foreground window is reconsidered when the break expires.
- Normal application startup remains silent: the window focused before launch is not treated as a new recognition visit, and ordinary pending-detail entries do not automatically open review popups. A task stopped specifically by Windows sign-out is the intentional exception and reopens that exact entry for review after sign-in. Recognition resumes on the next real foreground-window change, while other pending entries remain visible in History.
- Window rules edited by double-click or row context menu, with empty-space creation and delayed foreground-window/process capture inside the rule dialog.
- Idle handling separates brief and long pauses. Only detected idle intervals strictly shorter than five minutes enter the configurable rolling four-hour short-idle total; five minutes or longer is reviewed independently and never contributes to that total. Brief intervals persist across timer entries while tracking, and portions older than four hours expire automatically. At the configured total the app asks whether to cut every retained interval from its original log. Yes clears the batch and allows another reminder after one new threshold; No retains it, skips 2x, and asks again at 3x, 4x, and every following multiple. Excluded-software visits remain entirely separate under their per-app setting. Idle, unavailable-session, and excluded-software Keep/Cut reviews stay always on top until answered. If another long idle interval finishes while a normal idle review remains open, its full interval is retained and reviewed immediately afterward as `Double trouble!`; further repeats queue in the same one-at-a-time order, so dialogs never stack.
- Output-only idle protection keeps listen-only and normal calls, sustained foreground render audio, and playing video from becoming idle time. Windows communications ducking identifies labeled calls even with a muted or disabled microphone; otherwise foreground audio must remain active for 10 continuous seconds. Windows media sessions reported as video or unclassified playback qualify, while explicit music/images, notification sounds, system sounds, and ordinary background audio do not. Settings exposes independent enabled-by-default call/audio and video switches plus live `Call active`, `Foreground audio active`, and `Video playing` status. Detection never opens capture endpoints, requests microphone permission, samples content, or stores audio/media observations.
- Settings offers two explicit Windows-session behaviors. `Stop the running timer` closes the entry when Windows locks, signs out, or sleeps, then opens that exact entry's task-and-description popup after unlock, resume, or the next sign-in. `Keep running and review unavailable time` keeps the timer active and asks whether to Keep or Cut the inactive interval after return; the same review is restored after a real sign-out. Choosing Cut creates an exclusion, and live timer/tray elapsed values then show the resulting net time.
- Return prompts shown after lock, sleep, sign-out, or persisted session recovery are titled `You're back! What you were working on?`. This applies both to stopped-entry details and to the Keep/Cut inactive-time review when the timer continued. Ordinary timer, tray, stop-detail, and normal idle popups retain their standard headings.
- History is grouped by day by default, with a more prominent 14 px total aligned to the Duration column in each day header. Clicking a History column header instead sorts the entire currently visible filtered result set by that specific column, ascending then descending; equal values retain newest-first order. This flat sorted mode exposes `Clear sorting` to restore day grouping and also clears automatically when leaving History. Resolved software labels and bold colored description tags are available as History and Reports filters. History also has a live Description text filter that searches the loaded date range by case-insensitive partial content and clears with the other filters whenever History is re-entered. Entries whose recorded start/end intervals intersect another entry show a compact red pair of stacked opposing arrows immediately before their value in the Duration column. Overlap detection uses the same minute precision as the visible Start and End columns, so an end and start both displayed as 12:13 are adjacent even if a timer endpoint contains hidden seconds; overlaps crossing a visible minute boundary remain marked.
- History entry rows remain visually neutral after clicking: no persistent selection fill or outline is shown. Hover feedback remains visible, and internal extended selection is preserved for multi-entry payment updates and row context actions.
- Right-click one completed History entry and choose `Continue` to immediately start a new unpaid manual entry with the same client/project, saved task, description, and tags. The original log is unchanged. If another timer is active, it stops at the exact timestamp the continued entry begins; software usage and idle exclusions are recorded afresh instead of being copied. Entries whose project or saved task was removed cannot be continued.
- In the Add/Edit time entry dialog, tabbing into an editable text, date, or time value selects its complete contents. The first mouse click into an unfocused value does the same, so typing immediately replaces the old value; a later click can still place the caret precisely.
- History's Add/Edit time-entry dialog accepts a whole hour such as `13` and interprets it as local `13:00`. Its task chooser exposes the same direct typing interaction as the tracking bar: choose a saved task or click and type a new name. Save entry or Enter reuses a case-insensitive match or creates that task inside the selected project before assigning the entry.
- Right-clicking a specific History day heading or that day group's empty area and choosing Add entry prefills both entry dates with the clicked local day. The calendar fields remain fully editable before saving; adding from general empty space keeps the normal current-date default.
- In a new History entry, changing Start date immediately copies that date into End date. End remains independently editable afterward, and existing-entry editing does not force either historical date to follow the other.
- History and Reports provide immediate `This month`, `This week`, and `Today` date-range shortcuts beside the calendar field. Month selects the complete calendar month, week selects Monday through Sunday, and Today selects one local calendar day.
- When History’s `Wrap text` view option is enabled, cell text wraps at whole-word boundaries and can also break after `_`, `-`, `/`, or `\`, and at camelCase/PascalCase boundaries. These extra wrap points are invisible: stored and displayed text is unchanged.
- Right-click any History column header and choose `Hide column`, or use the three-line view-settings menu and its `Columns` submenu to show or hide fields. Column visibility, order, and widths form the current view; changing them reveals Save Current View in the page-title row, and saved layouts are restored on subsequent launches.
- `Restore default` now lives in the same History view-settings menu. Restoring remains an unsaved change until Save Current View is pressed, so an accidental restore does not overwrite the saved layout.
- Reports uses the same column workflow: right-click a task-summary header and choose `Hide column`, or use the three-line view menu to show hidden columns and restore the defaults. Column visibility and resized widths are synchronized across every project group and its aligned `Project total` row; changing either reveals Save Current View, which persists the report layout for later launches. `Time + idle`, immediately beside normal `Time`, adds back only individual excluded idle intervals no longer than the per-profile Settings limit (60 minutes by default and at most one hour). `Calls` reports the net time from entries explicitly marked as calls, grouped with their projects and tasks. A second project-share donut beneath the existing project/client chart visualizes that inclusive duration while the normal report totals remain unchanged. Paid and Unpaid are intentionally omitted from the report table; payment filtering and `Set as paid` context actions remain available.
- Selecting a Reports project keeps the project group visually neutral, while selected task rows retain the existing gray selection state. Project selection still works for keyboard actions and the project context menu.
- Tags are recognized while typing, shown without the `#`, and assigned distinct colors. A tag created from a timer, entry, recognition reminder, or project-scoped Software editor belongs to that project by default, so it is offered only inside that project. Add/Edit Tag exposes an explicit `Global · every project` scope for shared tags, and the Tags grid shows each tag’s project/client scope. Existing installations migrate their prior tags as global so saved descriptions and suggestions remain available. Editing one description remains local to that log; renaming a managed tag still updates its exact uses.
- Per-project daily, weekly, and monthly targets use the same local calendar boundaries as Reports: today from midnight to midnight, the current Monday-through-Sunday week, and the whole current calendar month. Every target independently chooses either active time or `Time + idle`; the latter uses the same configurable short-idle limit as Reports and is preserved when the target is edited, moved between cadences, or managed from Project Settings.
- Clients &amp; Projects includes a dedicated Targets tab. Its compact project filter offers All projects, Global targets, and each active `Project · Client`; it resets to All projects whenever the tab is entered. Right-click empty space to add a named daily, weekly, monthly, or one-time target, optionally scoped to a project or left as an All projects target. One-time targets have no configured date: they accumulate from creation until completed, remain visible through Sunday of their completion week, and disappear from target surfaces on Monday. Target progress uses its selected active-time or time-plus-short-idle metric with the same calendar boundaries as Reports; targets remain editable by double-click or row context menu.

A project may have multiple daily, weekly, monthly, or one-time targets, and any existing target can change cadence without being recreated. Project Settings lists every target assigned to that project and supplies dimmed Daily, Weekly, and Monthly ghost rows for missing cadences; a ghost is not persisted until hours are entered through its editor. The Projects table and pinned sidebar summarize each project by cadence, while Reports keeps every individual monthly target. Deleted targets are physically removed. Targets belonging to a removed project are deleted with that project and cannot appear as archived target rows.
- Reports monthly-target rows are visually passive: pointing at or selecting a target does not add a hover fill, selection background, or focus outline. Hit testing remains active so double-click editing and right-click target actions continue to work. Lowering accepts decimal hours or `H:MM`, must remain below the outstanding amount, and leaves the target showing both remaining debt and the dated reduction. Every adjustment is a dated, reversible ledger event; editing the correlated project target exposes `Bring debt back`, which restores all active reductions and cancellations without erasing their audit records.
- Project Settings can opt into carrying an unmet completed monthly target into the next month as target debt. The sidebar, Reports targets, and scheduled review show only its compact positive amount (`+5h`, `+30 min`, or `+3h 49 min`). Project debt uses the summed targets for each cadence and is repaid only by surplus over the daily summary first, otherwise the weekly summary, otherwise the monthly summary. Normal target hours never pay down the debt.
- Settings can optionally show one scheduled Target Review notification when any project has a weekly or monthly target. Choose the weekday and whether it is the first, second, penultimate, or last occurrence of that weekday in the month. The dark reminder lists current weekly/monthly progress and every outstanding carried debt; it never repeats on the same scheduled date.

- Per-project PLN/USD/EUR hourly rates, report values, target progress, and expanded UTF-8 CSV export.
- Monthly-first reports with editable dates, client/project/task/tag/payment filters, project-grouped totals, nested task summaries, and right-click drill-down into filtered History. The upper-right chart card switches between `Projects`, which preserves the selected report range and filters, and `Clients`, which shows all current-calendar-month time grouped by client. Both donut charts show sexagesimal hours/minutes, percentage shares, and a matching legend in the same space.
- Nested task summaries in each Reports project group are ordered by latest activity in the selected range, newest first. Total duration no longer controls their default order.
- Entering History resets it to the full current calendar month, from its first through final day, with all filters cleared. If a new month has no entries yet, History opens the most recent month containing logs instead, so existing history never appears missing. Entering Reports resets it to the current month through today. Report-to-History drill-down keeps its intentional range and row filter.
- Every editable date uses a minimal white line-art calendar button and a fully dark calendar popup with themed navigation, weekday labels, day states, and month/year views; manual entries keep date and local time as separate controls.
- The shared database and automatic UTF-8 monthly log files are stored together in `Documents\TimeTracker`; each month is written to its own `TimeTracker-Logs-YYYY-MM.csv` file and edits remain synchronized.
- Per-profile SQLite remains the local source of truth. Optional configured Trello and Google Sheets integrations are the only network features; unknown window titles are processed in memory and never stored.
- Optional launch at sign-in and single-instance activation.

Data is stored in `Documents\TimeTracker`. The built-in Default profile retains `TimeTracker.db` and its monthly files directly in that folder for backward compatibility. Additional profiles use isolated `Profiles\<profile-id>` folders containing their own `TimeTracker.db` and readable `TimeTracker-Logs-YYYY-MM.csv` files; `profiles.json` stores only the local profile list and active profile ID. Before schema upgrades, timestamped database backups are created inside the affected profile. Existing tags are preserved as global within their original profile, while newly discovered tags are linked to the entry’s project.

Profiles separate app data for organization and shared use, but they are not password-protected Windows security accounts. Anyone with access to the same Windows user and its Documents folder can access the local files.

Foreground process names are stored only when a timer is running, because they are part of the requested time entry. Raw window titles—especially unknown titles—remain in memory only and are never written to the database.

## Run from source

The solution targets .NET 10. From PowerShell at the repository root:

```powershell
dotnet restore ProjectTimeTracker.slnx
dotnet run --project src\ProjectTimeTracker.Windows\ProjectTimeTracker.Windows.csproj
```

Run tests with:

```powershell
dotnet test tests\ProjectTimeTracker.Tests\ProjectTimeTracker.Tests.csproj
```

## Build the Windows release

```powershell
.\scripts\build-release.ps1
```

This publishes a versioned, self-contained, single-file x64 application and creates a standard per-machine MSI installer in `outputs\installer`; Windows requests administrator approval when installing it. A trusted publisher certificate is not part of the source tree. For a production-signed installer, pass `-CertificatePath` and `-CertificatePassword`; the script signs and timestamps the MSI with the Windows SDK signing tool.

## Architecture

- `ProjectTimeTracker.Core`: portable domain records, platform interfaces, recognition, and prompt policy.
- `ProjectTimeTracker.Infrastructure`: SQLite repository, schema, recovery, reporting, and CSV export.
- `ProjectTimeTracker.Windows`: WPF UI, tray, foreground-window hook, idle/session adapters, notifications, and autostart.
- `ProjectTimeTracker.Tests`: recognition, focus-visit reminder suppression, persistence, recovery, reporting, and CSV coverage.

The SQLite layer uses `Microsoft.Data.Sqlite.Core` with Windows' system SQLite provider. This avoids shipping the native SQLite package currently flagged by NuGet security auditing and leaves provider selection at the platform-host boundary.
